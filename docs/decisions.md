# Decisions

Why the setup looks the way it does. Recorded so these are not re-litigated.

## `dark-ansi` instead of a custom theme

Claude Code's `theme` setting accepts exactly six values — `dark`, `light`, and their
`-daltonized` and `-ansi` variants (verified against the 2.1.274 binary). There is no
custom-theme mechanism.

`dark-ansi` renders through the terminal's 16 ANSI colours. `~/.config/alacritty/colors.toml`
is generated by `chroma` from the current wallpaper and carries a "do not edit by hand"
header. Pointing Claude Code at the ANSI palette therefore gives a genuinely custom theme
that re-colours itself on every wallpaper change, with no file to maintain and nothing to
hand-edit.

The same rule governs the statusline: ANSI indices 0-15 only, never hex. A hardcoded
colour would drift out of sync the first time the wallpaper changed.

## ECC is not installed

The `ecc` marketplace was registered but never installed. It ships 61 agents and 246
skills. Skill selection degrades as the index grows, and 246 third-party entries would
swamp the 34 existing ones plus the synced set. Its README also claims "182K+ stars" and
"Anthropic Hackathon Winner", neither of which holds up for that repository.

Deregistered rather than left dormant, so it does not get enabled by accident.

## Three official plugins, not six

Enabled: `context7` (current library docs — the Codex setup already mandates Context7 and
Claude Code had no equivalent), `plugin-dev` (authoring the hooks and skills here), and
`github`.

Deliberately skipped: `code-review`, `code-simplifier`, and `security-guidance`. Claude
Code already ships `/code-review`, `/simplify`, and `/security-review` as built-ins.
Installing the plugins would put two competing implementations in the index and make
skill selection worse, not better.

## Permissions instead of blanket bypass

The previous setup had `skipDangerousModePermissionPrompt: true` and **no** permission
rules at all — maximum blast radius with zero guardrails.

The allowlist was derived from 117k historical Bash invocations in the transcripts, not
guessed: `go test` (817), `cargo test` (373), `git status`/`diff`/`log` (703 combined),
plus the read-only shell tooling actually in use. Zero force-pushes ever appeared, so
those are denied outright. `rm` appeared 93 times in legitimate use, so it is `ask`
rather than `deny`.

`defaultMode` is `acceptEdits`: file edits stay friction-free, unrecognised shell
commands prompt again. Switch to `default` if the prompts turn out to be tolerable.

## `settings.json` is merged, not copied

The CLI writes to `settings.json` itself — `enabledPlugins` changes whenever `/plugin`
runs. The Codex installer copies its config file wholesale; doing that here would
silently revert plugin changes. `install.sh` merges with `jq` and preserves CLI-owned
keys, and `doctor.sh` asserts `enabledPlugins` survived.

## No safety-guard hook

A `PreToolUse` hook blocking destructive commands was considered and dropped. The
permission `deny` and `ask` lists cover the same ground declaratively, and a hook that
can fail closed can wedge every session on the machine. Every hook here exits 0 on every
path.

## The Stop hook needs an edit marker

A Stop hook that fires on any dirty tree is noise in a repo that is usually dirty. Instead
`format-edited.sh` drops a per-session marker, and `finish-check.sh` stays silent unless
this session actually edited something. Read-only and conversational sessions say nothing.

## Duplicate document skills removed

`pdf`, `docx`, `pptx`, and `xlsx` existed twice: local K-Dense copies in
`~/.claude/skills/` and Anthropic-maintained copies under `~/.claude/skills/synced/`.
Both appeared in the index. The synced copies are authoritative and kept; the local ones
are removed (and backed up) at install time.

## Porcelain parsing

`git status --porcelain=v1` marks an unstaged edit as `" M file"` — with a leading space.
An early version of the statusline and both git-reading hooks matched on a leading
non-space character and therefore never detected modified files. All three now match by
exclusion (`grep -v '^??'`). Worth remembering when adding another git-reading script.
