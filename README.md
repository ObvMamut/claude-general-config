# Supercharged Claude Code

A versioned, reproducible Claude Code setup: global instructions, a palette-aware
statusline, quality-gate and session-context hooks, a curated permission allowlist,
three output styles, four skills, and two subagents.

`~/.claude` is **output**. This repository is the source.

## Install

```sh
./install.sh
./doctor.sh
```

Restart Claude Code afterwards — settings, hooks, skills, and output styles are read at
startup.

`install.sh` is safe to re-run. Everything it replaces is backed up under
`.install-backups/<timestamp>/`, mirroring the path inside `~/.claude`.

## What it installs

| Repo path | Installs to |
|---|---|
| `claude/CLAUDE.md` | `~/.claude/CLAUDE.md` |
| `claude/settings.json` | **merged into** `~/.claude/settings.json` |
| `claude/statusline.sh` | `~/.claude/statusline.sh` |
| `claude/hooks/*.sh` | `~/.claude/hooks/` |
| `claude/output-styles/*.md` | `~/.claude/output-styles/` |
| `claude/agents/*.md` | `~/.claude/agents/` |
| `claude/skills/*/` | `~/.claude/skills/` |

`settings.json` is merged rather than copied because the CLI writes to that file itself
(`enabledPlugins`, `extraKnownMarketplaces`). A blind copy would silently revert any
plugin change made through `/plugin`.

## Never touched

- `~/.claude/skills/synced/**` — synced from the claude.ai account. Anything written
  there is lost at the next sync.
- `~/.claude.json` and `~/.claude/.credentials.json` — CLI state and secrets.

## Appearance

The theme is `dark-ansi`, which renders through the terminal's 16 ANSI colours rather
than a fixed palette. Since `~/.config/alacritty/colors.toml` is generated by `chroma`
from the current wallpaper, Claude Code re-themes itself whenever the wallpaper changes.
Claude Code has no custom-theme setting; this is how you get one.

The statusline follows the same rule — ANSI palette indices only, never hex — so it
never drifts out of sync with the terminal.

Optional Alacritty additions are documented in `terminal/alacritty-snippet.toml`. They
are **not** applied by the installer; that config is hand-maintained.

## Output styles

Select with `/output-style`:

- `terse` — code and diffs first, no recap. Engineering sessions.
- `research-report` — findings with units, sources, and as-of dates. Market and
  scientific work.
- `tutor` — stepwise, checks understanding, withholds the final answer. Revision.

## Scope boundary

Free tiers, local tools, and existing OAuth only. No paid or metered API, no new
credential, and no commercial service without an explicit request. Hooks and background
work are permitted; schedulers, daemons, and notification pipelines are not configured.

## Maintenance

Use the `claude-config` skill — it encodes the edit → `install.sh` → `doctor.sh` →
restart → commit loop, and the constraints that are easy to violate.

Design decisions and the reasoning behind them are in `docs/decisions.md`.
The original build plan is `PLAN.md`.
